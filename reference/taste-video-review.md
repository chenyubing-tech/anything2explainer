# 成片审美设计与终审

本规则将 Leonxlnx/taste-skill 的网页设计原则改编为视频审美规则。来源版本为 `f6b76575f949707b4e3c37cd86cb44b0b98643e8`（SKILL 标注 2.5.1）；出处及 MIT 许可见 `../THIRD_PARTY_NOTICES.md`。这是本项目的视频适配，不是原作者的视频评审器，也不代表运行过其网页 gate。

## 1. 借鉴什么，如何适配

| taste-skill 来源 | 审美判断 | 本项目的视频适配 |
|---|---|---|
| `SKILL.md` §1–2、`cards.md` The fragment on it | 先看主题，展示真正的产品或工作对象 | 每个镜头能指出正在解释的物体、过程或证据；通用机房、光球、无关仪表盘不能代替主题 |
| `layout-v4.md` §2 | One section per screen | 一个节拍一个主要结论，一个镜头一个视觉主角；允许连贯的多节拍演示 |
| `layout-v4.md`、`system.md` | Equal edges、one system | 文字、卡片、图表的边线有依据；统一字阶、间距、边框与圆角，不要求所有镜头机械对称 |
| `photos.md` Art direction | One visual world | H3、实拍与代码共享可识别的光线、材质、色调和主角位置；不靠全片压黑来伪装统一 |
| `SKILL.md` §2、`photos.md` Art direction | 换图、换构图；同一物体不撑满全页 | 连续镜头有语义推动的远近、全局/局部、过程/结果变化；重复裁切同一素材不算新创意；允许有意回扣 |
| `motion.md` Why it moves、`moments.md` | 动效有目的，少数值得记住的时刻 | 讲检索就取出证据，讲权限就挡住访问；不为避免静止添加呼吸、扫光；高光数量沿用本项目预算 |
| `copy-voice.md`、`copy.md` | 具体事实、自己的声音 | 画面标题说清对象与变化；标签不堆空泛口号，不只是逐字重放旁白 |
| `SKILL.md` Checklist、`gate.md` | 检查实际结果，修复后再查，公开遗留 | 对最终导出视频正常速度通看，并检查逐帧与边界；类型检查和 bundle 成功不能代替审美验收 |

不迁入网页的随机配色/布局抽签、hover/点击、响应式尺寸、联系地址、无图注、Stop hook、网页资源数量及 WebGL gate。用户确认的深海黑金、字幕、来源标注、Remotion 帧驱动动画和视频节奏规则优先。网页的真实摄影偏好不限制用户授权的 H3 原创场景；生成示意与真实证据仍需区分。

## 2. 设计前先写一张方向卡

分镜阶段在项目内建立 `script/visual_direction.md`，简短写清：

- 主题、观众与一个核心结论；贯穿例子和主角是什么。
- 已确认的配色、文字层级、间距、边框、材质和光线；不用另开一套风格。
- 哪些画面需要精确代码、哪些需要真实资料、哪些交给 H3；每种媒介解决什么表达问题。
- 每章的构图变化与高光时刻，及两三处共同物体/形状/动作接力。
- 要避免的模板痕迹，例如反复“胶囊 + 三卡片”、机房空镜、每镜头同一慢推和扫描线。

对每个动效问“删掉它会损失什么理解”；无答案时删减。H3 提示词沿用方向卡的材质和光线，为代码和字幕留出空间。新片可变化构图，不随意更换已确认主题。

## 3. 审核输入与顺序

在每版成片渲染后执行，和技术 QC 一起进入修复清单。输入是该版实际视频、逐帧目录、分镜、时间轴、方向卡、H3 实际素材清单与前一轮报告。

1. **正常速度完整通看，带声音。** 记录版本/视频路径/分辨率/fps/总时长，以及实际看过的范围；评估节奏、理解负担、旁白与画面关系。静帧不能证明节奏自然。无法播放或未完整通看时，结论为 `NOT_REVIEWED`，列出已查范围。
2. **全片缩略表。** 观察构图是否重复、主次是否一致、连续镜头是否同样拥挤或同样空。缩略表只用于定位问题，不替代完整通看。
3. **逐镜头与边界核查。** 每镜头查首帧、入场中段、落位、语义变化、离场与末帧；H3 检查实际文件和选段。镜头边界前后各约 0.5 秒以正常速度复看，再按需看连续帧。frame 范围与 timecode 都按该版输出记录。
4. **技术证据。** 使用 `frame_metrics.py`、`motion_check.py` 结果辅助定位，阈值以 `composition-and-light.md` §6–7 为准。静止占比不直接判错；代码图元连通域阈值不能直接判定 H3 场景是否合格。
5. **修复与复验。** 每个问题给出最小有效修法，改后重新渲染受影响段并回归两侧边界；最终 PASS 前重新确认最终导出的完整视频。不能用旧版本截图证明新版本通过。

## 4. 逐镜头八项评审

每镜头八项分别记 `PASS / FAIL / WARN / NOT_REVIEWED`；不要用总平均分掩盖失败项。每个 FAIL/WARN 有可定位证据及改法。

| id | 维度 | 观察问题 | 常见有效修法 |
|---|---|---|---|
| T01 | 主题与语义 | 画面真在讲这句话吗；隐藏标题后还能指出核心对象/动作吗 | 用证据页取代机房，用实际流程取代通用仪表盘；抽象概念可用贴切隐喻 |
| T02 | 主次与构图 | 第一眼看哪里；主体是否够大；同屏是否有两个争抢的标题或光源 | 放大主角、弱化配角；移除无用框和标签，不用增加装饰填空 |
| T03 | 排版与可读性 | 字阶、边线、留白是否稳定；字幕与正文是否互抢；金底文字是否可读 | 对齐共同边线、缩减文案、用深字配金底；按输出尺寸和实际播放尺度看 |
| T04 | 素材与视觉世界 | H3 主体/动作完整吗；有伪文字、形变或风格突变吗；代码压住视频主角吗 | 重选入出点、重生成具体动作、匹配光线或换构图；不直接加黑幕 |
| T05 | 动效与节奏 | 是有意义的变化还是小点装忙；是否读完还等、刚落位就切；是否抢旁白 | 调整动作与节拍，压掉空等；保留必要读图时间，复杂图允许更长 |
| T06 | 衔接与因果 | 共同物体/形状/方向是否接上；开头结尾有残留、跳位、露底或突然重置吗 | 改生成提示词与选段构图、保留锚点、调整层序和真实重叠，再润饰特效 |
| T07 | 变化与记忆点 | 是否连续重复同一三卡布局、同一视频换裁切；是否每镜头都想做高光 | 根据叙事换全局/局部或过程/结果；保留章级重点，删重复动作 |
| T08 | 文案与事实 | 标题具体吗；术语/数字一致吗；生成示意是否被当成事实；占位文字是否仍在 | 核实来源、简化标签、修正矛盾；未生成的素材明确记未完成 |

每条问题使用 `问题 id / T编号 / 严重度 / 镜头 / timecode / 帧范围 / 看到的现象 / 影响 / 证据路径 / 最小修法 / 复验状态`。审美评语应是“SC28 曲线与字幕同时争抢、查询主角不可辨”，不是“高级感不足”。

## 5. 交付结论

报告写到 `qc/taste_v<N>.md`，格式见 `taste-review-report-template.md`。最终技术报告链接到它。

- **PASS**：实际最终视频已完整通看；全部镜头和必查边界覆盖；无未解决高/中项，低项不超过项目既定上限（当前 ≤5）；所有保留项明确。技术 QC 同时通过后才能称成片验收通过。
- **FAIL**：存在影响主题、阅读、事实、动作完整性或衔接的可修高/中项，修后对同一问题 id 复验。
- **OPEN**：存在暂时无法修复的高/中项或其他未满足项，如素材不可用。列清遗留、原因和影响，不能写成 PASS，也不能由模型自行豁免事实错误或不可读内容。
- **NOT_REVIEWED**：没有实际视频或只做了静帧/源码检查；不得写“成片审美已通过”。

借鉴 taste 的有限轮次和公开遗留：同类问题避免无效重复重跑；一轮初审加两轮复验后，先汇总仍未解决的 OPEN 项与根因，继续可行的修复；不把“满三轮”当作自动完成、强制停工或必须询问用户的理由。用户要求继续时继续；用户明确接受保留项时记录其指示。

终审先报结论与实际观看范围，再报最影响观感的三处、所有未解决项与已修证据。明确区分“已接入评审规则”和“已评审一条真实成片”。
