# 空间动效、主体变形与代码 3D 创作方向

这是用户确认的后续创作偏好与实施、评审要求。适用于任意科普主题。本文件只定义方向，不表示模板已经实现三维引擎、自动跨媒体变形或 H3 生成调用；当前两段二维机制预览也不作为这些能力的验收样例。

## 1. 优先级与表达目标

默认追求有空间关系、主体接力和明显形态变化的高动态科普画面。关键机制、尺度变化和因果关系，优先考虑以下四种方向，并按表达价值组合：

| 方向 | 观众看到什么 | 解释什么 |
|---|---|---|
| 复杂空间穿行 | 镜头进入结构、穿过通道或层级，再拉回看整体；前中后景有真实的遮挡与视差 | 内外关系、尺度、路径、层次与传播 |
| 跨媒体主体变形 | 同一个可辨认主体从代码图形延展为实体，再进入生成或资料场景；返回时仍能认出 | 抽象模型与可感知现象如何对应 |
| 代码图形演变为 3D | 点、线、面、图标或图表从平面展开、挤出、拆解、组装，成为可绕行观察的结构 | 构造、空间连接、组成与变化机制 |
| H3 原创运动镜头 | 为当前论点新生成具体的空间、过程和镜头运动，随后与代码动作接力 | 难拍过程、微观空间、尺度体验与视觉想象 |

先设计观众能看见的大动作，再安排标签和局部细节。缩略尺度下也应能认出进入、展开、重组或穿行的变化。小点循环、卡片淡入和轻微推近可作辅助，不能据此宣称完成上述高动态目标。

强动态围绕因果与主角组织，每节拍有一个主导动作；空间运动中可以连续多次切换景别，不按旧镜头的一次运镜上限限制。为核心结论保留读图窗口，密集运动后允许安静地确认结果；不要求全片每秒都有大动作，也不强制每镜头使用所有方向。扫光和 Glitch 的原预算继续约束装饰效果，不用它们给空间叙事计次数。

## 2. 空间穿行要先有路线

在分镜或 `script/visual_direction.md` 中记录：观看对象、空间尺度、相机起点/路径/终点、注视对象、经过的关键结构、节拍和落位后能读出的结论。路径必须让观众理解为什么进入、经过什么、为何离开；避免无目的地绕圈或穿墙。

- 用前景遮挡、中景主体、远景参照建立尺度；切换微观/宏观时给共同锚点或尺度提示。
- 相机运动与主体运动分开设计，避免两者同时快速反向导致失去方向。接力前后核对运动方向、速度变化、透视和主体大小。
- 需要穿入、绕背面或看到内部时，采用能提供这些视角的真实几何或匹配素材。平面缩放、倾斜和分层可作过渡，但不把它们称为完整三维穿行。
- 字幕、导航和精确数据保持屏幕可读；必要标签可跟随主体投影，但应处理遮挡和透视，不把标签反复甩出画面。

## 3. 跨媒体变形先确定主体身份

每处承接写清：同一主体是什么、变形前后对应的轮廓/特征/部件、颜色材质、位置大小、朝向、运动与遮挡、代码到媒体的交接帧。至少保留能认出主体的共同特征；不能把前一物体淡出、另一无关物体淡入就写成主体 morph。

选择实际可行的实现方式：可控几何/路径插值、模型变形目标、纹理映射、遮挡接力、轮廓遮罩或按锚点匹配切换。实际资料只做诚实的标注或模型对应，不能把后加的变形包装成真实拍到的过程。生成示意同样保留其性质。

H3 支持参考图、首尾帧时，可用代码或 3D 渲染的交接帧约束主体；参数以实际工具支持为准。不支持时，明确采用构图匹配、分段桥接或遮挡承接。需要的分割、跟踪、几何或生成能力未具备时，列出缺口并完成可行的设计，不能把普通叠化算成已实现变形。

## 4. 让代码图形成为三维解释对象

优先复用同一组语义参数或几何数据，让平面与空间形态有对应关系：线延伸成管线或轨道，节点形成空间连接，平面展开成剖面，部件挤出后拆解和组装。参数变化应同时驱动模型和解释标注，避免 2D 与 3D 各说一套。

有明确空间价值的图形才做三维。精确读数、公式和密集表格可继续保留平面表达；图表进入空间后仍要交代坐标、变量和尺度，不能用透视夸大差异。漂亮的实体模型不能替代机制正确和结构对应。

实施时按工程条件选择：

- 分层、浅景深感或有限视角可用已有平面图元与 CSS 透视，明确属于 2.5D。
- 真实三维相机、表面、遮挡与模型变化，可评估 Three.js / React Three Fiber / 与当前 Remotion 版本兼容的集成，或其他可稳定导出的三维工具。先核对依赖、资源和渲染条件，不假设已安装，也不指定虚构 API。
- 动画与相机由帧号和共享时间轴决定；禁止依赖自由运行的渲染循环、墙钟或未固定种子的随机数。预渲染三维片段也要登记时间、源文件和交接帧。
- 测渲检查真实导出中的光照、遮挡、透明材质、纹理、闪烁和性能。二维 DOM 数量指标不能证明三维渲染合格，也不作为禁止三维的理由。

## 5. H3 承担原创运动与空间创作

按 `generated-video-direction.md` 为不同论点设计不同的新镜头。计划中写明相机路线、主体动作、空间尺度变化、前后交接姿态、参考帧和精确代码叠加区。一个镜头可以包含连续的多节拍运动，但须围绕一个主要叙事任务，保持方向和主体可追踪。

提示词应说明具体运动和结束状态，如进入结构内部、跟随介质穿过通道、从局部拉回整体；不要只写 cinematic、dynamic 或“高级感”。生成精确文字、数字和图表仍由代码接管。主动生成新空间和新动作，不以反复裁切同一素材冒充原创镜头增加。

工具不可用时，明确列为待生成，保留镜头计划、提示词和代码交接设计；不自动退化为一组普通卡片后宣称达到用户偏好。若使用其他实现完成部分表达，记录实际实现和剩余差距。

## 6. 分镜交付与评审

需要高动态的段落在现有分镜中补充下列信息即可，不另造一套庞大的配置协议：

`解释目标 / 主体 / 2D、2.5D、真实3D或H3的实际分工 / 主导动作与相机路线 / 2D到3D的参数对应或跨媒体身份锚点 / 前后交接姿态 / 阅读落位 / 所需工具与素材 / 计划、已实现或待验证状态`

构建笔记和终审记录实际文件、已实现动作、关键帧和正常速度复看范围。按 `taste-video-review.md` T01/T04/T05/T06/T07 检查：

- 空间路径是否解释了内外、层级或尺度；代码形态到实体是否有明确对应。
- 主体在变形与换媒介后能否追踪；非设计性扭曲、穿模、遮挡跳变与闪烁是否出现。
- 大动作是否确实可见，节拍与因果是否接上，关键结论是否有阅读时间；不把运动事件数量作为质量分。
- H3 是否实际生成了不同新素材；三维是否实际渲染，不能用文档、占位图或倾斜卡片证明。

这是设计偏好与审查依据，不是所有镜头必须上 3D 的数量配额。未实现的动作标明待做；没有真实输出或未正常速度通看时，不给整段空间动效审美 PASS。
