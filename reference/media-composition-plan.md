# 图片、视频、代码图表统一编排与强动态场景方案

状态：方案已获用户批准并完成第一版实现。实际接口见 `scene-composition.md`；真实素材与技术检查记录见 `../template/qc/scene-composition-validation.md`。原方案以下作为设计依据保留，最终完整视听与 H3 验收范围以验证记录为准。

## 1. 背景与目标

用户希望代码、图片和 H3 视频协调地出现在同一个场景，并显著增强场景内部的动态表现与吸引力。第一版目标是形成“持续演变的场景”：运动有足够的尺度、层次和连续性，表达清楚叙事；图片、图表和视频围绕同一主角接力。

实施前有四个缺口（本轮已补齐，以下保留为背景）：

- 视频固定在代码层下面，无法按场景决定谁是主画面。
- 图片没有统一轨道；进退场、裁切和运动靠镜头各自实现。
- 视频延展与转场装饰分别计算时长，18 帧配置可能对应 36 帧装饰；省略配置时两者默认值也不一致。
- 现有预览用文字和渐变模拟视频，尚未证明真实媒体拼接、源帧与解码可靠。

本方案面向任意科普主题，题材、主角和动作由用户主题与调研结果决定。场景接口、动效组件和转场预设不得内置 RAG、文档或其他具体题材；`examples/rag/` 只是一个示例。

本方案提供场景编排、场景内动效、统一切换、素材验证与成片审美验收。它是 Remotion 本地工程改造，无新增数据库或远程业务 API。

## 2. 核心结构：场景、图层、节拍

```text
Composition：全局配音 / 字幕 / 导航
  SceneTrack：决定当前场景和相邻场景的重叠
    SceneSurface：一个完整画面，含背景与以下图层
      MediaLayer：图片 / 视频，可全屏、卡片或局部窗口
      GraphicLayer：代码图表、流程、文字
      EffectLayer：语义动作与强调特效
      CameraRig：控制指定的场景图层
    BoundaryTransition：只接收统一算好的边界进度
```

每个场景可包含多种媒体。图层显式定义层级和展示区域，视频可以是主画面、图表中的局部窗口或环境层；精确数据、标签与图表由代码绘制。字幕、进度条和常驻导航保持屏幕坐标，独立于内容运镜。

### 数据与组件接口

| 类型 / 组件 | 关键字段 | 职责 |
|---|---|---|
| `SceneSpec` | `id, start, duration, layers, beats, camera` | 声明完整场景与名义时间区间 |
| `SceneLayer` | `id, kind, role, order, viewport, motion` | `kind` 为 image/video/graphic；role 为主角、环境或标注 |
| `ImageLayer` | `src, fit, focus, viewport` | 使用 Remotion `Img`，统一图片裁切和运动 |
| `VideoLayer` | `src, sourceInSeconds, sourceDurationSeconds, sourceFps, playbackRate, fit, focus` | 使用 `OffthreadVideo`，明确源时间与成片帧的映射 |
| `GraphicLayer` | `Comp` | 渲染已有代码镜头或新的动态图表 |
| `SceneBeat` | `at, duration, subject, action` | 指定语义节拍与主导动作 |
| `BoundarySpec` | `fromScene, toScene, durationFrames, preset, direction` | 一个边界只声明一次转场，at 由场景起点计算 |
| `compileSceneTimeline()` | 场景、边界、总帧数 → 渲染计划 | 集中校验、扩展与进度计算，渲染组件不重复计算 |

第一版动作使用有限的类型和组件，复杂场景允许自定义 React 组件，避免发明庞大的动画配置语言。

## 3. 场景内的强动态设计

### 动作强度

默认采用“强主动作 + 相关次级动作 + 运镜跟随”。强度来自视觉关系发生明显变化：大幅移动、布局重构、视角转换、图表结果揭示与主体接力。一个节拍的主动作要一眼可见；关联元素可以同时联动。

| 画面 | 主动作 | 配合动作与运镜 |
|---|---|---|
| 主题图片 | 从整体推近局部，分离结构或叠加解释 | 聚焦主体、显露内部层次，镜头跟随当前解释对象 |
| 曲线或柱状图 | 轴线建立后数据生长，关键结果接管画面 | 标记沿曲线运行；视角从全局推进局部再回到对照 |
| 对照数据 | 随参数变化更新状态、排列或占比 | 变化项与结论同步强调，镜头从整体移到关键差异 |
| 图片集 | 前中后景展开为有层次的空间 | 相机穿行或推向一张图，选中的图接成视频窗口 |
| H3 场景 | 一个清楚的主体完成动作 | 代码轮廓跟随预设锚点；画面完成动作时接回代码对象 |
| 流程或空间图 | 物体、能量、信号等沿路径运动，结构随解释展开 | 主路径突出，关联结构顺次响应，镜头跟随当前主角 |

H3 中的对象跟随在第一版使用人工设计的锚点关键帧，不承诺自动识别和跟踪。精确数字、术语与图表刻度不交给生成视频。

### 节拍组织

- 一个场景可包含多个节拍；在旁白重音、关系变化或结论处组织可见的主动作，不机械每秒切一次。
- 主体入场通常约 8–16 帧；结构重组约 16–30 帧；景别转换约 18–36 帧，按复杂度调整。以 30fps 为当前工程基准。
- 细节读取、复杂图表与结果揭示保留停留；停留期间可继续与语义有关的动作。
- 支持强推进、短促强调、局部视差、路径追踪与画面扩展；不默认整屏频闪和无意义抖动。
- 每节拍明确一个主导运动，避免相机高速运动时所有小标签也在反向乱飞。

与旧规则的衔接：用户本次要求提高动态强度，旧的“每镜头最多一次运镜”需在新场景模式中改为“每节拍一个主导运动”；章级重点、文字可读、字幕安全区和动作语义仍保留。实施时同步更新工作流与 QC，避免新模式被旧规则误判。

## 4. 转场只由一个边界控制

`durationFrames` 统一表示完整转场的总时长。默认 18 帧即总共 0.6 秒，不再分别为两侧各算 18 帧。

内部全部使用 0 起、右端不含的区间。旧 `from/to` 为 1 起含端点，由适配器统一转换：`start = from - 1`、`endExclusive = to`。

边界帧 B、总时长 d：

```text
pre = floor(d / 2)
post = d - pre
转场范围 = [B - pre, B + post)
p = clamp((globalFrame - (B - pre)) / (d - 1), 0, 1)
```

d 为 0 时直接切换；d 为 1 时直接选入场画面，避免除零。裁剪到成片范围后进度仍按原始区间计算。首场景无前置场景、末场景无后置场景，不生成不存在的边界。

所有图片、视频、代码层的入退场、遮罩与装饰均使用同一个 p。双侧冲突、相邻过渡相互覆盖、id 重复或场景缺口应在编排校验时指出，不静默叠加。

### 第一版转场预设

| preset | 效果 | 适用场景 |
|---|---|---|
| `cut` | 直接承接 | 已匹配物体、位置或动作的两画面 |
| `dissolve` | 前画面作完整底层，后画面逐渐覆盖 | 图片与视频的自然衔接 |
| `reveal` | 后场景沿方向展开，边缘装饰可选 | 有明确流向、窗口或结构边界 |

叠化将前场景作为不透明完整底图、后场景按 p 覆盖，避免两个透明画面一起露出黑底。每个 `SceneSurface` 提供背景，内容图层可保持透明。场景的临时层序只由边界编排决定，不固定“所有视频在所有代码下面”。

物体匹配由共同锚点和场景内动作完成；第一版不将“自动物体变形”包装成一个已经可用的通用 preset。焦点光、网格、扫描线为可选润饰，不能替代两个画面的真实连接。

## 5. 源时间与同步

全局音频和字幕时间不因叠化自动缩短。重叠通过场景的渲染句柄扩展实现，名义时间轴和总时长保持明确。

- 场景局部帧 = 全局帧 − 名义开始帧；既有代码组件在适配层中保持原来的本地帧约定。
- 第一版默认将前后扩展帧钳制到本场景首/末有效帧，通过 Remotion 帧控制实现短暂保持；视频不会因为提前挂载而把源片段提前播掉。
- 视频 `sourceIn` 定义为名义开始帧对应的源时间，源帧换算考虑素材 fps 与 playbackRate；禁止简单假定所有视频都是 30fps。实施时通过媒体元数据确认可用区间。
- 图片、代码、视频使用相同的边界 p；新场景中的内部入场按场景编排执行，避免场景叠化和组件自带退场重复压暗。
- 素材过短、源起点越界、读取失败、缺失文件均在预检报告中明确失败；不静默循环，也不假装存在额外可播放帧。

## 6. 跨题材真实媒体验证

验收结构规定媒体组合与动态能力，不规定某个故事、物体或具体题材。图片→视频→图表只是验证组合之一，成片按解释需要自由排序，不把每段科普强行套成相同四步模板。

| 必测组合 | 动态能力 | 验收重点 |
|---|---|---|
| 图片 → 视频 | 从静态全貌或细节接到实际动作 | 主体位置、尺度与运动接续，无闪黑与源帧漂移 |
| 视频 → 代码图表 | 从现象进入机制、结构或数据解释 | 保留共同焦点，图表实际展开或生长，视频主角不被误盖 |
| 图片/视频 + 代码同场 | 媒体表现现象，代码补结构、路径或指标 | 有主次、标注可读、字幕独立，多个图层同步联动 |
| 代码 → 图片/视频 | 从原理或结论返回可感知的现象 | 进退场同步、方向一致、动作有完整收束 |

第一版至少用两个不同科普题材验证同一套组件，防止引擎被单一样片绑死。以下为可选选题，不写入公共接口：

| 可选题材 | 图片 / 视频作用 | 代码与强动态作用 |
|---|---|---|
| 物理：共振 | 展示物体实际振动现象 | 振幅随频率变化、扫频抵达峰值，镜头由现象推进曲线 |
| 生物：细胞运输 | 展示微观空间和运输过程（生成画面标为示意） | 分层显露结构、路径推进、局部聚焦与状态变化 |
| 地理：台风形成 | 展示云系和海面，真实观测资料保留来源 | 路径、风向、热量与指标逐步建立，切换区域与局部尺度 |
| 工程：电池充放电 | 展示器件整体、内部结构示意 | 剖面展开、粒子沿路径运动、能量与曲线同步变化 |
| 历史：交通演进 | 用有出处的图片或资料视频展示变化 | 时间线推进、地图路径展开、尺度与数量对照 |

每个验证片段建议约 10–15 秒，长度服从动作完整性与阅读需求。两段合计覆盖上述全部组合；复用同一套公共渲染组件，只更换主题内容、素材和节拍。

验证交付：可播放 MP4、实际素材清单与来源、边界关键帧、技术结果与 taste 审美报告。当前仓库没有可用的真实 H3 视频；实施时先盘点实际工具与素材，可用 H3 则生成对应主题的新素材，否则可用相关实拍验证轨道能力，明确记为“实拍验证，尚未验证 H3”。不能用占位渐变或文字冒充视频。

图片或真实媒体不足时报告缺口，继续完成独立的实现工作；真实媒体验收保留未完成状态。生成的视觉隐喻不作为真实科学实验或历史事件的证据。

## 7. 实施顺序与代码落点

| 顺序 | 预计修改 | 交付结果 |
|---|---|---|
| 1 | `common/sceneTypes.ts`、`sceneTimeline.ts` | 统一数据结构、区间适配、边界进度和校验 |
| 2 | `common/MediaLayer.tsx`、`SceneTrack.tsx` | 图片/视频统一展示，场景与图层的顺序、视口、局部帧控制 |
| 3 | `Main.tsx`、`TransitionLayer.tsx`、旧 Footage 适配 | 全局 HUD 与字幕独立；新场景使用统一边界；旧工程逐步迁移 |
| 4 | 场景动效组件与 `MixedMediaPreview` | 实现放大聚焦、布局重构、路径运动和镜头接力；接真实图片与视频 |
| 5 | 规则文档、检查与验证输出 | 技术回归、完整段落 MP4、关键帧、taste 评审与总结 |

原 `ShotDef`、`FootageSpec` 通过显式适配器保留读取能力；新场景不同时挂载旧 `FootageTrack`，避免重复播放。旧镜头自带的完整退场逐个检查，仅迁移段落调整，不全库盲目删除动画。

新增类型与组件都在本地渲染链路中，无数据库迁移、远程 API、定时任务或发布服务。

## 8. 检查与验收

自动检查重点是编排正确性：

- 默认/0/1/奇数转场时长、片头片尾、短场景、冲突边界和旧帧号适配。
- 两侧共享 p，实际转场区间准确为 d 帧；名义源起点不漂移；fps 换算和源区间不足有明确结论。
- typecheck、bundle、图片解码与真实视频渲染，固定帧重复渲染结果稳定。

人工验收重点是最终画面：

- 两侧切换无露底、闪黑、代码遮住主角、重复进退场或突然回到首帧。
- 强动作清楚可见，图表是实际生长/重排；图片有空间与视角变化，视频动作能完成。
- 镜头跟随主体，关键结论可读，字幕与导航稳定；不靠频闪和无意义抖动制造刺激。
- 正常速度带声音完整看不同题材的验证段落；按 `taste-video-review.md` 逐镜头评审主题、构图、排版、素材、节奏、衔接、变化与事实。
- 报告区分机制实现、真实素材技术验证与 H3 审美验证；没有实际成片不能称通过。

## 9. 方案中的默认决策与依赖

先实现通用编排能力，再用两个不同题材的真实素材段落验证；看过强动态效果后再扩大应用范围。深海黑金是当前用户确认的默认主题，画面材质、构图和动效根据科普内容设计；默认 30fps，普通转场总长 18 帧，叙事节拍与各片配音对齐。动态强度以主体运动和结构变化为主要手段。

外部依赖只有合适的真实媒体和实际可用的生成工具。第一版不引入自动跟踪、任意物体 morph、帧插值或新的三维引擎；需要立体感的部分优先由层次、透视与已有 Remotion 相机表达。第一版已按以上顺序实施；后续新片仍须独立完成素材与视听验收。
