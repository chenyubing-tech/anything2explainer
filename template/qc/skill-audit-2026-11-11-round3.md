# Skill 交叉检查与覆盖范围

日期：2026-11-11。基线：277ee00。检查目标是核对入口、参考、对外说明、实际调用与证据之间的关系，不将可选美化记作缺陷，不把未实测能力写成已经通过。

## 为什么前两轮仍有漏项

同一规则重复维护在入口、参考、两种语言 README 和脚本说明中。前两轮完成了已定位修正与对应验证，但没有覆盖所有规则副本；尤其是 README 的完整用法/FAQ、分镜正文和 TTS 文件头仍保留旧流程。首轮报告已记录的检查结果有效，但不代表全库所有说明已一致。把这些副本留到后续才发现，是前两轮覆盖不足。

本轮将重复生产步骤改为引用 `reference/production-workflow.md`，由入口决定任务范围、由专题参考描述模式接口；历史样例和旧镜头预算保留其明确适用范围，减少同一流程的多处副本。

## 结果与边界

本轮发现并修正的是规则副本未同步、旧新模式说明和调用说明不准确，没有复现新的场景引擎运行故障。代码阅读核对了名义局部帧、边界延展、裁切、倍速与源长度计算；现有测试覆盖相关时序不变量，本轮未新增这些组合的实际视频渲染证据。

没有重渲染视频，没有执行新的 TTS 或 H3 生成。H3 实际调用、通用自动主体 morph、Unix 新建工程完整成功流水线和现有样例的完整带声音审美终审仍未验证；终审状态仍为 NOT_REVIEWED。Three.js 测试装载器的既有 CommonJS 弃用提示不影响本次 21 项测试结果。

后续复查可从本表逐项核对改动影响和对应证据。运行缺陷、文档漂移、可选审美改进及尚未验证能力分别记录，不能因为又发现一个可选改进就推翻已通过的实际检查。
