## 真实媒体与代码的渲染检查

新增可重复运行的 `npm run check:scene-render`，使用本机已安装的 Chrome 和当前锁定依赖，将实际 SceneTrack/sceneTimeline 源文件复制到隔离项目。没有调用既有太阳/火山预览作为本次测试结果。

- 3 个场景，每个 30 帧；合成 320×180、30fps，共 90 帧 PNG 序列。
- 图片 → 实际 H.264 视频 → 代码图形；源视频颜色编码每帧位置，代码白条宽度编码局部时钟。
- 视频从源 0.5 秒裁入、2 倍速；18 帧叠化与 18 帧 reveal，检查前后扩展保持首末源帧，不抢播、不重置局部时钟。
- 90 帧均实际渲染、解码；179 个颜色采样通过，1 个位于遮罩抗锯齿边缘的采样按预设排除；1,760 个白条/局部时钟采样通过。
- 单独重渲第 38 帧，与序列对应帧的全部 RGB 像素一致。
- 证据保存源文件哈希、源视频哈希、解码像素哈希、采样数和重复帧结果：`scene-render-runtime-evidence.json`。

此项没有配音、字体、3D 或 H3；它是媒体/代码与边界的技术夹具，不是审美样片，也不等于新的 MP4/音轨导出已验收。复用现有安装依赖，不代表 npm 从零安装或 Unix scaffolding 全成功。

## 保留边界

- H3 工具实际生成、通用自动主体 morph 与真实 TTS 服务/声音效果未在本轮验证；没有把本地测试音轨记作声音验收。
- 新建工程脚本的 Unix zsh/rsync 成功路径未验证，本机未提供这两个工具。本轮隔离源工程验证不代替该路径。
- 真实渲染只覆盖上述组合及当前机器，不能推导所有视频格式、硬件或新主题均通过。
- 现有示例的完整带声音审美终审仍为 NOT_REVIEWED；当前已经确认的是这些复现缺陷已修复及列出的技术路径已通过。
